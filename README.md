# SignoreBot

Сайт и скачать: [https://aumphaadr.github.io/SignoreBot/](https://aumphaadr.github.io/SignoreBot/)

Twitch-бот, который живёт у стримера на компьютере. Команды в чате, реакции
на награды за баллы канала и на события (фолловеры, подписки, bits, рейды),
автоматические шатауты, банворды и медиа-алерты в OBS. Одно окно и иконка
в трее.

Три вещи, ради которых он такой.

**Всё у вас.** Никаких серверов, вкладок браузера и чужих сайтов, которым
надо доверять свой аккаунт. Настройки, медиа и токены Twitch не покидают
компьютер, токены лежат в системном хранилище. Авторизация — по коду на
странице Twitch, пароль приложению не сообщается. Бот работает, пока
работает ваш компьютер, и не зависит от того, жив ли чей-то сервис.

**Интерфейс объясняет себя сам.** Отдельного руководства нет, потому что оно
не нужно: у каждой настройки подсказка рядом, у каждой капсулы на карточке
пояснение при наведении, которое собирается из ваших же данных («команда
`!барабан` имеет алиас `!drum`», «медиа отправляется на оверлей: Аудио»,
«команду `!звук` могут вызывать: Модераторы»). Предпросмотр показывает алерт
ровно так, как его увидит зритель. Переменные вроде `{user}` копируются
кликом, а не запоминаются. Если бот чего-то не может, он говорит об этом
словами и предлагает, что сделать, а не молчит.

**Бесплатно и без ограничений.** Нет платной версии, подписки, лимитов на
количество команд или оверлеев, «премиум»-функций и рекламы. Всё, что умеет
бот, доступно каждому сразу, и так останется: это принцип проекта, а не
маркетинговый этап.

## Установка

Сборки — на [странице релизов](https://github.com/Aumphaadr/SignoreBot/releases).

- **Windows 10/11**: установщик или portable `.exe`. SmartScreen может
  предупредить о неизвестном издателе — «Подробнее → Выполнить в любом случае».
- **Linux**: `.deb` (`sudo apt install ./SignoreBot_*.deb`) или AppImage
  (`chmod +x`, запускать как есть).

Обновления приложение проверяет само по этой же странице релизов и
показывает плашку со ссылкой; самозамены файла нет — скачали новую сборку,
запустили, настройки и медиа на месте.

## Первый запуск

1. **Авторизация** — два аккаунта: стример (события канала и чтение чата) и
   бот (сообщения в чат). Нажмите «Авторизоваться», введите показанный код на
   открывшейся странице Twitch. Для бота удобнее «Скопировать ссылку» и
   открыть её в браузере, где залогинен именно он. Бот стартует сам, как
   только оба аккаунта готовы, и дальше держит токены свежими без вашего
   участия.
2. **Оверлеи** — у каждого оверлея кнопка «Копировать URL»; вставьте адрес в
   Browser Source в OBS. Адреса ведут на `127.0.0.1`, поэтому
   порядок запуска OBS и бота не важен. Если включить интеграцию с OBS
   (obs-websocket), бот сам пропишет адреса и будет перезагружать источники.
3. **Реакции** — Команды, Баллы канала, События, Периодическое. У каждой
   реакции текст в чат и/или медиа на оверлей. Кнопка «Показать» в редакторе
   рисует предпросмотр ровно так, как это будет в OBS; «Тест на оверлее»
   отправляет в OBS прямо сейчас.

Переезжаете со старой версии — на вкладке «Состояние» есть «Импортировать
config.json»: настройки переведутся в новый формат, а медиа сами скопируются.

## Что умеет

- **Команды** — `!команда` с алиасами, кулдауном и правами (роли или список
  ников). Текст в чат собирается из блоков: автор, цель, случайный зритель,
  случайное число, набор фраз, переменные.
- **Баллы канала** — реакция на активацию награды; список наград подтягивается
  с канала.
- **События** — новый фолловер, подписка, переподписка, подарочная подписка,
  bits, рейд, watch streak; у каждого свои переменные (`{user}`, `{tier}`,
  `{viewers}`, …).
- **Периодическое** — сообщения по интервалу со смещением и таймлайном, чтобы
  таймеры не срабатывали хором; «сработать при старте» по желанию.
- **Шатауты** — автоматический `/shoutout` зрителям из списка при первом
  сообщении, очередь с учётом лимитов Twitch, ручной шатаут любого.
- **Банворды** — жёсткий и мягкий режим, автоматические варианты написания
  против латиницы, повторов букв и разделителей; модераторов можно не
  проверять.
- **Оверлеи** — сколько угодно, у каждого адрес с ключом доступа; очередь,
  антиспам, анимации появления и текста, хромакей, картинка + звук, видео.
- **Медиа** — каталог файлов с предпросмотром и уборкой неиспользуемых.
- **Настройки** — порт и доступ из локальной сети, папка данных на любом
  диске (с переносом), закрытие в трей или выход, экспорт/импорт без секретов.

Бот следит за собой: если оверлеи не открыты ни одним Browser Source, панель
покажет предупреждение, а при свёрнутом окне придёт системное уведомление.

## Где что лежит

- **Windows**: `%APPDATA%\ru.aumphaadr.signorebot\` (или другая папка, если вы её перенесли в настройках)
- **Linux**: `~/.local/share/ru.aumphaadr.signorebot/`

```
config.json        настройки без токенов
media/             медиафайлы
config-backups/    копии конфига перед миграцией и импортом
logs/              логи по дням (30 дней), deleted_messages.log
secrets.json       только если системное хранилище недоступно (права 0600)
```

Токены — в системном хранилище: KWallet / GNOME Keyring на Linux,
Credential Manager на Windows.

## Чего пока нет

- Автозапуска вместе с системой.
- Самообновления — только проверка и ссылка на релиз.
- Второй копии приложения: повторный запуск показывает окно первой. Это
  намеренно — две копии портили бы друг другу одноразовые refresh-токены.

## Для тех, кто хочет форк

**Стек**: Tauri 2 (ядро на Rust: axum, tokio, reqwest, keyring), панель на
React 19 + TypeScript + Vite. Типы IPC генерирует ts-rs.

```
npm install
npm run tauri dev                               # окно + Vite HMR + автопересборка Rust
SIGNOREBOT_DATA_DIR=/tmp/sb npm run tauri dev   # отдельные данные и токены (боевой keyring не трогается)
npm run test:rust                               # тесты ядра; полный прогон генерирует src/api/generated/*.ts
npm run icons                                   # пересобрать src/components/Icon/icons.ts из src/assets/icons/*.svg
npm run fonts                                   # пересобрать встроенные шрифты оверлея из src-tauri/fonts/manifest.json
npm run site                                    # собрать сайт из site/ в docs/ (GitHub Pages)
npm run site:serve                              # посмотреть собранный сайт: http://127.0.0.1:8765/
npm run build:linux                             # deb + AppImage (с tools/fix-appimage.sh)
npm run build:windows                           # portable .exe кросс-компиляцией с Linux (cargo-xwin)
npm run tauri build -- --bundles nsis           # на Windows: установщик
npm run release:collect                         # сложить бандлы в release/ под именами релиза на GitHub
```

Особенности, о которые легко споткнуться:

- **ts-rs** пишет файлы целиком: генерировать типы только полным
  `cargo test`, отфильтрованный прогон оставит частичный файл.
- **AppImage** после `tauri build` нужно прогнать через
  `tools/fix-appimage.sh`: linuxdeploy кладёт в AppDir библиотеки GStreamer,
  а плагины остаются системные — с двумя копиями `libgstreamer` видео и звук в
  панели не играют. Вторая половина проблемы — `AppRun` выставляет
  `GST_PLUGIN_SYSTEM_PATH_1_0` на пустой каталог — чинится в самом приложении
  (`lib.rs::fix_appimage_gstreamer_env`).
- **Иконки** — свои, 97 штук в `src/assets/icons/`. Генератор собирает их в
  один `icons.ts` (svgo + `currentColor` + поле по краям), компонент
  `<Icon name="…" />` типизирован по именам файлов. Добавили SVG — запустите
  `npm run icons` и коммитьте результат: панель собирается без генератора.
- **Шрифты оверлея** лежат в `src-tauri/fonts/` и описаны в `manifest.json`;
  `npm run fonts` генерирует байты для сервера (`fonts_gen.rs`), `@font-face`
  для панели и список для выпадающего меню. Добавить шрифт — положить TTF под
  OFL, дописать в манифест, пересобрать.
- **Twitch-приложение** должно быть типа Public (Device Code Flow без
  секрета); Client ID — в настройках, по умолчанию вшит наш. У форка будет
  свой репозиторий для проверки обновлений — адрес меняется в настройках.
- Переменные окружения: `SIGNOREBOT_DATA_DIR` (каталог данных, токены в нём
  файлом), `SIGNOREBOT_SECRETS=file|keyring`, `SIGNOREBOT_LOG` (фильтр логов).

Структура:

```
src-tauri/src/
  lib.rs            точка входа Tauri, трей, окно, single-instance
  core.rs           супервизор: авторизация → рантайм (EventSub, таймеры, shoutout), сервер, сторож оверлеев
  commands.rs       Tauri-команды (IPC)
  config/           схема v2 (schema.rs), миграция v1→v2 (migrate.rs), хранилище (store.rs)
  twitch/           auth.rs (Device Code), accounts.rs (токены, refresh), helix.rs, eventsub.rs
  engine/           диспетчер, реакции, банворды (Ахо-Корасик), shoutout, periodic
  overlay/          hub.rs (подключения, отложенная очередь), server.rs (axum), obs.rs (obws)
  updates.rs, media.rs, secrets.rs, logging.rs, paths.rs
src-tauri/overlay/  overlay.html, overlay.css, overlay-sw.js — встраиваются в бинарник;
                    тот же CSS импортирует панель, поэтому предпросмотр совпадает с OBS
src-tauri/tests/    ломатели, интеграционные тесты, фикстура конфига v1
src/                панель: api/ (IPC + сгенерированные типы), state/, components/<Вкладка>/
site/               исходники сайта: уроки (pages/), каркас, стили, маршрутизатор
docs/               собранный сайт (GitHub Pages): npm run site; картинки и шрифты лежат здесь
```

Протокол оверлея: `http://<host>:<port>/overlay/<path>?key=<ключ>` — страница,
она же открывает `ws://<host>:<port>/ws?path=<path>&key=<ключ>`. Сообщения
сервера: `config`, `playVideo` (см. `engine/mod.rs::send_media`), `clearQueue`,
`clearAll`; медиа — `/media/<file>?key=<ключ>`. `&debug=1` к адресу страницы
включает отладочную плашку.
