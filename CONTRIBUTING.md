# Правки и сообщения об ошибках

Самый полезный вклад в SignoreBot — сообщение об ошибке: реакция, которая не
сработала, оверлей, который не подключается, подсказка, которая говорит не то.
[Заведите issue](https://github.com/Aumphaadr/SignoreBot/issues/new): версия
(«Настройки → Обновления»), система, что сделали, что увидели и что ожидали
увидеть. Лучше всего приложить логи: вкладка «Логи» → «Экспорт». Прежде чем
выкладывать файл, просмотрите его: в логах бывают ники зрителей, названия
наград и адреса оверлеев.

Правки принимаются на условиях лицензии проекта — [MIT](LICENSE).

## Где что лежит

- [README.md](README.md) — установка и возможности; раздел «Для тех, кто хочет
  форк» — стек, команды, структура папок и особенности, о которые легко
  споткнуться.
- [CHANGELOG.md](CHANGELOG.md) — что изменилось для пользователя, по версиям.
- [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) — что взято со стороны и на
  каких условиях.
- Сайт-учебник: исходники — `site/`, собранный сайт — `docs/` (GitHub Pages).

## Как устроена правка

1. Ядро — Rust в `src-tauri/src/`, панель — React и TypeScript в `src/`,
   страница оверлея — `src-tauri/overlay/`. Новая логика ядра приходит вместе
   с тестами: рядом в `#[cfg(test)]` или в `src-tauri/tests/`.
2. Типы для панели (`src/api/generated/`) генерирует ts-rs — только полным
   `cargo test`: отфильтрованный прогон оставит частичный файл.
3. Интерфейс объясняет себя сам: у настройки — подсказка рядом, у ошибки —
   слова о том, что случилось и что делать, а не код движка.
4. Строка в [CHANGELOG.md](CHANGELOG.md) в разделе «Не выпущено». Номер версии
   назначает автор проекта.
5. Урок сайта правится в `site/pages/`, затем `npm run site`: `docs/`
   коммитится вместе с исходником. Версию сайт берёт из `package.json`, а
   дату и «что нового» — из раздела CHANGELOG этой версии, поэтому перед
   сборкой сайта раздел должен быть заполнен; `docs/version.json` с теми же
   данными читает приложение при проверке обновлений.

## Проверка перед публикацией

- `npm run test:rust` — все тесты ядра зелёные (полный прогон заодно обновляет
  типы для панели).
- `npm run test:overlay` — гонки подключения и переподключения оверлея;
  настоящий сценарий страницы с управляемыми WebSocket и таймерами, без OBS.
- `npm run build` — TypeScript и сборка панели без ошибок.
- `npm run check` заканчивается строкой «Все проверки пройдены»: внешние
  адреса, значки, шрифты, лицензии библиотек.
- `npm run site`, если менялись уроки, каркас сайта или значки на нём; `docs/`
  идёт в тот же коммит — проверка на GitHub сверяет его с пересборкой.
- Живая проверка — в окне приложения (`npm run tauri dev`) на отдельных данных:
  `SIGNOREBOT_DATA_DIR=/tmp/sb`, а в «Настройки → Сеть» этой копии — другой порт
  (например, 3011). Иначе открытый OBS получит страницу пробной копии вместо
  настоящего бота.

## Подготовка новой версии

Версия приложения должна совпадать в `package.json`,
`src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`. Для исправлений без
изменения формата данных обычно повышается последний номер: 1.0.5 → 1.0.6.

1. В корне проекта `npm version patch --no-git-tag-version --ignore-scripts`
   обновляет `package.json` и обе записи приложения в `package-lock.json`.
   Эта команда не создаёт коммит или тег. Если номер уже повышен, повторно
   её запускать не нужно — получится следующая версия.
2. Тот же номер записать в `[package].version` файла `src-tauri/Cargo.toml`
   и в `version` файла `src-tauri/tauri.conf.json`. Затем обновить запись
   своего пакета в Cargo.lock командой из корня проекта:

   ```bash
   cargo metadata --offline --manifest-path src-tauri/Cargo.toml --format-version 1 > /dev/null
   ```

   Версии сторонних зависимостей в lock-файлах при этом не повышаются.
3. Раздел «Не выпущено» в CHANGELOG превратить в `## 1.0.6 — 2026-10-04`
   (пример), с реальными номером и датой релиза. Это источник даты и списка
   изменений для сайта. Если выпуск отложен, перед публикацией поправить
   дату и пересобрать сайт.
4. Перед новой сборкой обнулить `sizes` в `site/release.json`: размеры
   предыдущего выпуска не относятся к новым файлам. Ноль означает, что
   размер пока неизвестен; после сборки его заполнит `release:collect`.
5. Выполнить `npm run site`: он пересобирает `docs/`, `docs/version.json`
   и ссылки на скачивание с новым номером. Эти файлы не редактируются вручную.
   Затем выполнить проверки из раздела выше.

Исторические версии в CHANGELOG, комментариях о миграциях, фикстурах и
замороженной спеке не заменяются массовым поиском.

## Сборка и публикация релиза

Из корня проекта на Linux, с установленными инструментами сборки:

```bash
npm run build:linux
npm run build:windows
```

Первая команда собирает DEB и AppImage, включая обязательную обработку
AppImage. Вторая собирает Windows portable через cargo-xwin. NSIS-установщик
собирается отдельно на Windows командой `npm run tauri build -- --bundles nsis`.

Перед следующим шагом проверить артефакты в `src-tauri/target/`.
`release:collect` копирует найденные portable exe и NSIS-установщики под
именами **текущей версии**, но не проверяет версию внутри бинарника. Старые
непересобранные exe/установщики нужно перенести из путей, которые использует
`tools/collect-release.sh`, либо пересобрать; один лишь бамп версии не
обновляет бинарники. Затем:

```bash
npm run release:collect
npm run site
npm run check
```

`release:collect` складывает файлы в `release/` и обновляет их размеры в
`site/release.json`; поэтому финальная сборка сайта выполняется **после**
него. Размеры отдельно собранного установщика или ZIP вне `release/`
нужно заполнить по фактическим файлам. Набор сторонних библиотек не менялся —
повторный `npm run licenses` для одного бампа номера не требуется.

Перед публикацией пройти ручные проверки на новых бинарниках. В релизный
коммит включить исправления, версии, lock-файлы, CHANGELOG,
`site/release.json` и собранный `docs/`. Создать тег `v1.0.6` (пример) на
этом коммите и GitHub Release с тем же тегом. Загрузить свежие артефакты с
точными именами из `docs/version.json`: например,
`SignoreBot_1.0.6-windows-x64-portable.exe`. Не переименовывать старые
файлы в новую версию.

Сайт с новым `docs/version.json` публиковать после появления файлов в
GitHub Release: иначе ссылки на скачивание ещё будут вести на 404.
После публикации проверить скачивание и «Проверить обновления» в старой
версии приложения.

## Правила

- **Всё своё — в репозитории.** Панель, оверлей и сайт ничего не грузят с
  других сайтов; `npm run check` не пропустит страницу, стиль или сценарий,
  который что-то грузит извне.
- **Значки — из набора Klaarheid Icons.** Символы Юникода и эмодзи вместо
  значков не ставятся. Исключение — знаки Twitch (Bits, баллы канала) в
  `src/assets/icons/twitch/`: в набор они не входят.
- **Страж проверен на обратном.** Новая проверка должна падать, если сломать
  то, что она сторожит, — это проверяется руками один раз, до публикации.

## Чужие файлы

Всё, что не создано для проекта, — библиотека, шрифт, картинка, звук —
добавляется, только если:

1. лицензия разрешает свободное использование, в том числе в коммерческих
   продуктах;
2. текст лицензии лежит рядом с файлом — как `Jost-OFL.txt` у шрифта Jost
   (у шрифтов это проверяет `npm run check`);
3. в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) появилась строка: что
   это, откуда, кто автор, какая лицензия и где файл лежит.

Всё, что нужно панели, оверлею и сайту, подключается своими файлами из
репозитория — не с чужих серверов, не через CDN и не прямыми ссылками на
файлы репозиториев GitHub и сайтов на GitHub Pages, в том числе набора
Klaarheid: GitHub не хостинг для раздачи файлов. `npm run check` следит за
этим сам. Ссылка для перехода — `<a href="https://…">` или `openUrl(…)` —
загрузкой не считается.

Библиотеки ставятся через npm и Cargo. `npm run check` сверяет лицензии всего,
что уходит к пользователю, — пакетов из `dependencies` и крейтов, которые
линкуются в бинарник, — с белым списком в `tools/licenses.mjs`. После смены
зависимостей `npm run licenses` пересобирает раздел «Библиотеки» в
THIRD-PARTY-NOTICES.md и список `third-party/rust-crates.md`. Лицензия не из
списка (GPL, LGPL, AGPL и подобные) или новый крейт под MPL-2.0 — повод
остановиться и решить, а не дописать исключение.

Значки берутся из набора [Klaarheid Icons](https://aumphaadr.github.io/Klaarheid-Icons/)
(MIT-0) командой

```
npm run icons:sync -- <папка набора> <имя значка> …
```

Она копирует файлы из папки `svg/fill` локальной копии набора (`git clone`)
в `src/assets/icons/klaarheid/` байт в байт, пересобирает
`src/components/Icon/icons.ts` и раздел «Значки» в THIRD-PARTY-NOTICES.md.
По сети команда ничего не качает и адрес вместо папки не примет. Без имён
она обновляет значки, которые уже лежат в папке; чтобы убрать значок, удалите
его файл и запустите `npm run icons` (`npm run check` напомнит о значках,
которые нигде не используются). Руками не правятся ни файлы значков, ни
`icons.ts`, ни этот раздел: обновлённый значок снова копируется из набора.
